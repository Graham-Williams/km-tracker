# Runtime dependencies, pinned EXACTLY on purpose. Two reasons, both learned
# the hard way — see CLAUDE.md "Dependency pinning" before loosening anything:
#
#   1. Reproducibility. The Dockerfile runs `pip install -r requirements.txt`,
#      so a `>=` floor installs whatever is latest at image-build time. This
#      file used to carry ranges and had drifted far from what prod actually
#      ran, which made "what is deployed?" unanswerable from the repo.
#   2. Dependabot. GitHub's `dependabot/fetch-metadata` misparses a *bounded*
#      range: `flask>=3.0,<4.0` produced the PR title "Update flask requirement
#      from <4.0,>=3.0 to >=3.1.3,<4.0" and was reported as
#      `version-update:semver-major`, so ci.yml's auto-merge gate (correctly)
#      refused a minor bump and the PR stuck forever. An exact pin produces
#      "Bump X from A to B", which parses correctly.
#
# Every version below is the version running in production. Transitive deps
# (Werkzeug, cryptography, httpx, ...) are left to the resolver; pin one here
# only when there is a specific reason, with the reason in a comment.
